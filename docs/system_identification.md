# システム同定

実機ロボットに決められた動作をさせ、記録したデータから **シミュレータと制御に必要な物理パラメータ** を推定する。
操作GUIの「システム同定」タブからワンボタンで実行でき、結果は `pc/config/robots/robot_XX.yaml` に保存され、
ファームウェアへの推奨ゲインも `set_param` で書き込める。

コード: `pc/src/coco_link/sysid/`（`experiments.py` 試験定義, `estimators.py` 推定, `runner.py` 実行）

---

## 1. なぜ同定するのか

- 同じ部品で作っても、モータのゲイン・不感帯・車輪径は **個体ごとに 5〜15 % ばらつく**
- 公称値のままでは、まっすぐ走らない・止まりたい位置で止まらない・隊形がずれる
- 同定したモデルを使うと (1) 車輪速度制御のゲインを理論的に設計でき、(2) シミュレータを実機に近づけられる

シミュレータの仮想ロボットには **隠れた真値（個体差）** が設定されている（`coco-sim` の右パネルに表示）。
シミュレータで同定を実行すると、推定値と真値の誤差が結果表に表示されるので、手法の妥当性を検証できる。

## 2. モデル

車輪ごとに次のモデルを仮定する（`robot/plant.py` のシミュレータもこの構造）:

$$
u_{\mathrm{eff}} = \operatorname{sign}(u)\,\max(|u|-u_0,\,0)\cdot\frac{V}{V_{\mathrm{nom}}}
$$

$$
\tau\,\dot\omega + \omega = K\,u_{\mathrm{eff}}
$$

| 記号 | 意味 | 同定する試験 |
|---|---|---|
| $u$ | PWM duty [-1, 1] | – |
| $u_0$ | 不感帯（静止摩擦・逆起電力などで回らない duty） | 2. ランプ |
| $V/V_{nom}$ | 電池電圧の比（電圧が下がると同じ duty でも遅くなる） | テレメトリ `batt_v` |
| $K$ | ゲイン [rad/s per duty] | 3. ステップ |
| $\tau$ | 時定数 [s]（慣性と摩擦で決まる） | 3. ステップ |
| $r$ | 車輪半径 [m] | 4. 直進 |
| $b$ | 実効トレッド幅 [m]（タイヤの接地幅などで設計値とずれる） | 5. 旋回 |
| $g_z^0$ | ジャイロのバイアス [rad/s] | 1. 静止 |

## 3. 試験と推定方法

すべての試験は **広い場所（前後 0.5 m 以上）** で、ビジョンにロボットが映る状態で行う。
試験 2, 3 はその場旋回なので場所をとらない。

### 1) ジャイロバイアス（3 s 静止）

静止中の $g_z$ の平均がバイアス、標準偏差がノイズ。

### 2) 不感帯（duty ランプ, 約 18 s）

左右の車輪を逆向きにして（その場旋回）、duty を 0 から `max_duty` まで 8 秒かけて増やす。
ランプが十分ゆっくりなら $\omega$ は定常値に追従するので、

$$
|\omega|\frac{V_{nom}}{V} = K\,(|u| - u_0)
$$

という **直線** になる。$|\omega| > 1$ rad/s の点を最小二乗で直線回帰し、切片から $u_0$ を求める（傾きは静的ゲイン $K$）。

**補正**: ランプ中の $\omega$ は入力より $\tau$ だけ遅れるので、$u_0$ は「ランプ速度 × $\tau$」だけ大きく出る。これを差し引く。

### 3) モータ特性（duty ステップ, 約 6 s）

duty を 0.3 → 0 → -0.45 → 0 → 0.6 → 0 とステップ状に変え、応答から $K, \tau$ を推定する。

**観測値の選び方（重要）**: ファームが送る角速度 `wl, wr` はローパスフィルタ（約 23 ms の遅れ）を通っているので使わない。
代わりにエンコーダ角の差分 $\bar\omega_k = \Delta\theta_k / \Delta t_k$（区間平均速度）を使う。

**(a) ARX モデル（線形最小二乗）**: 離散時間モデル

$$
\bar\omega_{k+1} = a\,\bar\omega_k + b\,u_{\mathrm{eff},k}
$$

の $a, b$ を最小二乗で求めると $\tau = -\Delta t/\ln a$, $K = b/(1-a)$。簡単だが、観測ノイズがあると偏りが出る。

**(b) 非線形最小二乗**: (a) を初期値として、一次遅れモデルを ZOH 入力でシミュレーションした区間平均速度

$$
\hat{\bar\omega}_k = K u_k + (\omega_k - K u_k)\frac{\tau}{\Delta t_k}\left(1 - e^{-\Delta t_k/\tau}\right)
$$

と実測の差の二乗和を `scipy.optimize.least_squares` で最小化する。結果表には両方の値が記録される（比較すると面白い）。

### 4) 車輪半径（直進, 約 10 s）

前進 → 静止 → 後退 → 静止。**静止区間** のビジョン位置の平均と、エンコーダ角の平均を比べる:

$$
r = \frac{\sum_i d_i}{\sum_i |\Delta\theta_i|},\qquad \Delta\theta = \frac{\Delta\theta_L+\Delta\theta_R}{2}
$$

静止区間どうしを比べるので、ビジョンとロボットの **時刻同期が不要**（実機で頑健な設計）。
直進中の向きの変化も記録される（左右の車輪径差の目安）。

### 5) トレッド幅（その場旋回, 約 10 s）

左旋回 → 静止 → 右旋回 → 静止。旋回角 $\Delta\psi$ をビジョン（30 Hz の角度を unwrap して積算）とジャイロ（バイアス補正して積分）の両方で求め、

$$
b = \frac{r\,\sum|\Delta\theta_R - \Delta\theta_L|}{\sum|\Delta\psi|}
$$

ビジョンが使えないときはジャイロの値を使う。両者の差はジャイロのスケール誤差の目安になる。

### 6) 検証（速度ステップ, 約 5 s）

`cmd_vel` でステップ指令を与え、車輪速度の立ち上がり時間（10→90 %）・オーバーシュート・定常偏差を表示する。
ゲインを書き込む前後で実行して比較するとよい。

## 4. 制御器の設計（IMC 法）

プラント $G(s) = K/(\tau s + 1)$ に対し、閉ループ伝達関数を $1/(\lambda s+1)$ にする PI 制御器は

$$
C(s) = \frac{\tau s + 1}{K\lambda s}
\quad\Longrightarrow\quad
k_p = \frac{\tau}{K\lambda},\quad k_i = \frac{1}{K\lambda}
$$

$\lambda$（試験条件で設定, 既定 0.05 s）が小さいほど速いが、ノイズ・モデル誤差に弱くなる。
さらにフィードフォワード $k_{ff} = 1/K$、$\tau_{ff} = \tau$（モデル逆系 $u = (\omega^* + \tau\dot\omega^*)/K$）を設定する。
これらは「ロボットへ書き込み」で `kp, ki, kff, tau_ff, u_deadzone, wheel_radius, tread` として送られる。

## 5. 実験設計の注意（ハマりどころ）

| 現象 | 原因 | 対策（実装済み） |
|---|---|---|
| τ が 2 割小さく出る | テレメトリ 50 Hz・制御 100 Hz だと、1 サンプル区間に duty 更新が 2 回入り、入力と応答の対応が最大 10 ms ずれる | 同定中は `telemetry_hz=100` に変更し、終了後に戻す |
| τ が大きく出る | ファームの角速度推定のローパス遅れを含めてしまう | エンコーダ角の差分を使う |
| 微分値がガタガタ | Wi-Fi の到着時刻揺らぎで Δt を測っている | テレメトリの `t_ms`（センサ取得時刻・ロボット時計）を使う |
| 不感帯が大きく出る | ランプ中の応答遅れ | ランプ速度 × τ を差し引く／ランプを遅くする |
| 速度ステップでオーバーシュート | 速度推定の遅れが偽の偏差として PI に入る | ファームで目標値にも同じフィルタを通す（firmware_spec §5.3） |
| 電池が減ると遅くなる | 同じ duty でも電圧で速度が変わる | モデルに $V/V_{nom}$ を入れ、ファームで電圧補償 |

シミュレータでの検証結果（`pc/tests/test_sysid.py`, 個体差 ±15 %）: 推定誤差は $K$ ≈ 1 %, $\tau$ ≈ 3 %, $u_0$ ≈ 3 %, $r$ ≈ 0.2 %, $b$ ≈ 1 %。

## 6. 手順（実機）

1. ロボットを広い場所に置き、ビジョンと操作GUIを起動。一覧にロボットが表示され、姿勢源が `vision` であることを確認
2. 電池が十分か確認（`batt_v` > 4.6 V 目安）
3. 「システム同定」タブ → 対象ロボットを選択 → 「同定開始」（全試験で約 55 秒）
4. 結果タブで当てはまり（R², グラフ）を確認
5. 「保存」→ `pc/config/robots/robot_XX.yaml`（Git にコミットしてチームで共有）
6. 「ロボットへ書き込み」→ 再度「6. 検証」だけ実行して改善を確認

## 7. 発展課題

- 左右の車輪半径を別々に同定する（直進中の向きの変化 $\Delta\psi$ から $r_R/r_L$ を求められる）
- クーロン摩擦・粘性摩擦を分けたモデルや、2 次系（モータインダクタンス）への拡張と AIC によるモデル選択
- PRBS（擬似ランダム 2 値信号）入力による周波数応答の同定、ボード線図の作成
- 同定結果の不確かさ（推定値の共分散、ブートストラップ）の評価
- MCAP ログからのオフライン同定（`Recording` を MCAP から再構成すれば `estimate()` をそのまま使える）
